Practica 03 - Bases de datos en la nube

Implementacion completa de la Practica 03 sobre la base de datos db_test (MySQL 8.0.46, servidor 127.0.0.1:40045): correccion del esquema, 72 triggers, 25 vistas, 7 roles con privilegios, rutinas y eventos, simulacion de 7,500 usuarios, poblacion de 7,000 productos por vendedores y verificacion integral.

Requisitos

  • MySQL Server 8.0.46 en 127.0.0.1:40045.
  • Cliente mysql y mysqldump en el PATH (o rutas completas de MySQL 8.0).
  • event_scheduler = ON y privilegios de administrador para crear roles, usuarios y eventos.

Orden de ejecucion

Ejecutar desde una consola con el cliente MySQL:

mysql --defaults-file="C:\Users\Public\my_practica.cnf" db_test < 01_schema/01_correccion_esquema.sql
mysql --defaults-file="C:\Users\Public\my_practica.cnf" db_test < 02_triggers/02_triggers_72.sql
mysql --defaults-file="C:\Users\Public\my_practica.cnf" db_test < 03_vistas/03_vistas_25.sql
mysql --defaults-file="C:\Users\Public\my_practica.cnf" db_test < 04_usuarios_roles/04_usuarios_roles_privilegios.sql
mysql --defaults-file="C:\Users\Public\my_practica.cnf" db_test < 05_rutinas/05_procedimientos_funciones_eventos.sql
mysql --defaults-file="C:\Users\Public\my_practica.cnf" db_test < 06_simulacion/06_simulacion_usuarios.sql
# Solo si se requiere regenerar el Test 2:
# mysql --defaults-file="C:\Users\Public\my_practica.cnf" db_test < 06_simulacion/06b_regenerar_test2.sql
# Poblacion de productos (ejecutar como seller1 y seller2):
mysql --defaults-file="C:\Users\Public\my_seller1.cnf" db_test < 06_simulacion/07a_poblacion_seller1.sql
mysql --defaults-file="C:\Users\Public\my_seller2.cnf" db_test < 06_simulacion/07b_poblacion_seller2.sql
mysql --defaults-file="C:\Users\Public\my_practica.cnf" db_test < 07_verificacion/08_consultas_verificacion.sql
powershell -ExecutionPolicy Bypass -File 07_verificacion/09_pruebas_acceso.ps1

Importante: si se vuelven a crear los procedimientos con DROP PROCEDURE, se pierden los permisos EXECUTE a nivel de rutina. En ese caso se debe re-ejecutar 04_usuarios_roles_privilegios.sql para restaurar los permisos de seller.

La simulacion de usuarios es repetible: elimina los usuarios t1_, t2_ y t3_ antes de regenerarlos. La poblacion de productos es aditiva; ejecutarla dos veces duplica los productos de cada vendedor, por lo que debe correrse una sola vez.

Cuentas y roles

Roles del sistema

Rol Proposito
superadmin Control total del servidor y de db_test.
admin CRUD sobre las 24 tablas operativas, lectura de bitacora y ejecucion de rutinas; sin DDL.
support Consulta general y actualizacion de pedidos, envios, devoluciones y cancelaciones.
seller Gestion de productos, categorias de producto y proveedores.
buyer Consulta de catalogo y gestion de carrito y pedidos propios.
common_user Catalogo, perfil propio y carrito.
user_not_registered Solo catalogo publico.

Cuentas remotas

Usuario Rol Contrasena
remoto_superadmin superadmin Sup3r#2026
remoto_admin admin Adm1n#2026
remoto_support support Supp0rt#2026
seller1 seller Sell3r1#2026
seller2 seller Sell3r2#2026
buyer1 buyer Buy3r1#2026
common1 common_user C0mm0n#2026
guest1 user_not_registered Gu3st1#2026

Todas las cuentas usan el host % y tienen su rol asignado como rol predeterminado. Las contrasenas con # deben ir entre comillas dobles en los archivos .cnf. MySQL muestra los roles como cuentas bloqueadas (account_locked = 'Y'); es el comportamiento normal de los roles y no impide su uso por las cuentas asignadas.

Vistas

  • Catalogo: vw_productos_por_categoria.
  • Trazabilidad (24): una vista por tabla operativa (vw_trazabilidad_usuarios, vw_trazabilidad_people, vw_trazabilidad_productos, vw_trazabilidad_categorias, vw_trazabilidad_productos_categorias, vw_trazabilidad_products_users_providers, vw_trazabilidad_carts, vw_trazabilidad_cart_items, vw_trazabilidad_orders, vw_trazabilidad_order_items, vw_trazabilidad_payments, vw_trazabilidad_payment_methods, vw_trazabilidad_payment_methods_types, vw_trazabilidad_user_payment_methods, vw_trazabilidad_payment_transaction, vw_trazabilidad_shipments, vw_trazabilidad_returns, vw_trazabilidad_return_items, vw_trazabilidad_refunds, vw_trazabilidad_user_addresses, vw_trazabilidad_address_components, vw_trazabilidad_order_cancellations, vw_trazabilidad_cancellation_items, vw_trazabilidad_users_wishlist_products).

Las vistas de trazabilidad incluyen los datos de la entidad y las columnas log_id, log_operation, log_db_user, log_record_id, log_description, log_date y log_status. La vista de usuarios excluye password y enmascara las referencias a metodos de pago.

Limitaciones y pendientes

  • GitHub: la rama Practica03 y la rama main ya se publicaron en https://github.com/Carballo1305/Practicas_BDN_correcion. El repositorio remoto contiene los ultimos commits de la practica.
  • Archify: la herramienta de documentacion no estaba disponible en el entorno. Los entregables equivalentes (diccionario de datos, MERE y evidencias) se generaron localmente en 08_documentacion/ para su carga manual.
  • Los privilegios heredados sobre la base db_test_7b (practicas anteriores) se conservaron intactos; no forman parte de esta practica.
  • Los datos de ejemplo de pedidos, carritos, pagos y envios no se poblaron porque el alcance solicitado se centro en usuarios y productos.
